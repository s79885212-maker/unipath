# Контракт отображения дат и стипендий

Техническая ветка `codex/site-quality`. По поручению владельца от 24 октября
исследовательские исправления временно выполняются в этой же отдельной ветке.
Существующие поля и тексты сохраняются. Новые поля необязательны для загрузки;
без них интерфейс честно показывает отсутствие проверенной связи/цикла.

## Дата и цикл

`status`: `confirmed`, `annual-rule`, `previous-cycle`, `not-confirmed`.
Для эффективного `confirmed` необходимо структурированное `cycleEvidence`:

```js
{
  id: 'example-entrance-2027',
  kind: 'scholarship',
  entryTerm: 'Autumn', entryYear: '2027',
  dateISO: '2027-03-01', date: '1 March 2027',
  status: 'confirmed',
  source: 'https://university.example/official-scholarship-page',
  verified: '2026-10-24',
  cycleEvidence: {
    basis: 'page-context', // или explicit-date
    entryTerm: 'Autumn', entryYear: '2027',
    source: 'https://university.example/official-scholarship-page',
    verified: '2026-10-24',
    quote: 'Дословный фрагмент официальной страницы, устанавливающий набор'
  },
  awardId: 'entrance', awardCategory: 'merit'
}
```

Пример иллюстрирует схему, это НЕ исследовательская запись и не источник.
`explicit-date`: дата с годом явно опубликована и привязана к указанному набору.
`page-context`: год установлен окружающим официальным текстом, даже если строка
даты не содержит года. `verified` сам по себе никогда не доказывает цикл.
`annual-rule`: ежегодное правило, цикл не установлен; ближайшим дедлайном не считается.
Для такого правила `date`/`displayDate` должны содержать только опубликованный
текст без приписанного года, `dateISO` и `entryYear` — `null`, пока год не подтверждён.
Предыдущий цикл имеет приоритет над доказательством. Старое `status: confirmed`
без `cycleEvidence` показывается как неподтверждённое для текущего набора;
исходный объект не изменяется. Нет анализа слов в `note`.

`kind`: admission (или прежние RD/EA/ED/regular/round-N/priority и др.), documents,
nomination, scholarship, aid (или financial-aid), deposit, reply — отдельные события.
Обязательность зачисления (`binding`) показывается только для admission-раундов.
Номинация и заявка на стипендию могут быть закрыты/предстоящими независимо.
`time` и `timezone` — только опубликованные значения; зона устройства не является
зоной университета. Без точного времени/зоны используется консервативная граница
окончания календарного дня, без показа выдуманного времени пользователю.

## Связь со стипендией

В `scholarships.merit[]` (включая записи других оснований), а также у
`scholarships.fullRide`, если это один конкретный проверенный award, используются:

```js
{ id: 'entrance', category: 'merit', entryTerm: 'Autumn', entryYear: '2027',
  name: 'Example entrance scholarship', deadline: null }
```

Событие связывается только при точном совпадении `awardId` ↔ `id`,
`awardCategory` ↔ `category`, `entryTerm` и `entryYear`. `kind` события должен быть
scholarship/nomination/aid/financial-aid. Допускаются также явно связанные
`documents` и `admission`: например, ранняя заявка на поступление для участия
в конкретном конкурсе Pearson. Любое событие с `awardId` относится к этому
award и не выбирается как общий ближайший срок поступления в вуз. Метка
admission сохраняется, дата не переименовывается в scholarship. Названия не
сопоставляются эвристически. Карточка крупнейшей стипендии при наличии её
точного id использует тот же renderer, что и именованные стипендии и таблица.
Ни одна общая дата помощи не переносится автоматически на все awards.
Для опубликованного ежегодного правила без установленного набора допустим
явный `deadlineScope: 'annual-rule'` у конкретной стипендии. У неё и события
`entryTerm`/`entryYear` должны быть `null`; у события также `dateISO: null`,
`status: 'annual-rule'` и `cycleEvidence.basis: 'annual-rule'`. Идентификатор и
категория по-прежнему совпадают точно. Это справочная связь ежегодного правила,
она никогда не подтверждает срок конкретного набора. Событие другого набора,
категории или с точной датой не подходит. Пример: `id: 'additional-entrance',
category: 'merit', deadlineScope: 'annual-rule', entryTerm: null, entryYear: null`.
`deadlineScope: 'no-separate-application'` означает подтверждённое автоматическое
рассмотрение без отдельной стипендиальной заявки; карточка сообщает об этом,
не присваивая ей дедлайн другой стипендии.
Карточка и таблица используют один источник дат и один механизм статусов.
Если связь не проверена, карточка объясняет это и направляет к отдельным датам
и официальной странице; старый текст `deadline`, если есть, остаётся как справка.

## Направления и стоимость

Строгие фильтры продолжают использовать `programs`/`englishTaughtPrograms`.
`partial` и `not-checked` не означают отсутствие программы. Карточки совпадений
не включают предположения; непроверенные варианты перечисляются отдельно.
Для кампусных/языковых условий используем существующий `programEvidence` и
текст профиля; общеуниверситетское наличие английского не доказывает язык поля.
`match.annualCost` не заполняется автоматически из неполных цен. Конфликт
официальных сумм всегда остаётся конфликтом; исторический курс не является текущим.

## Условная SAT-политика: область доказательства
`academics.sat.policy: conditional` означает, что требование зависит от школьной системы. `label`, `cycle`, `note`, `source`, `verified` ограничивают подтверждённый маршрут. Это не обещание приёма без теста для остальных систем; SAT-требование не подтверждает альтернативу ACT. Пример SMU: American School System, календарь 2026–27; ACT=null, Fall 2027 не установлен. Существующая схема не расширялась.

## Подтверждённая кредитная нагрузка: совместимое дополнение

Существующий `match.annualCost` допускает дополнительный `calc: 'credit-load'`.
Остальные значения и старые записи не меняются. Для нового значения нужны:
`basis: 'tuition'`, `period: 'year'`, положительные `perCredit` и целое
`creditsPerYear`, `source` ставки, `workloadSource` нагрузки (оба HTTPS),
`academicYear`, `verified`, `workloadVerified`, а также `min=max`, равные
округлённому до центов произведению. Неустановленная нагрузка не заменяется
обычными 30 кредитами. Пример UNBC: 1040.15 × 30 = 31204.50 CAD за 2026–27.
Это подписанный расчёт UniPath для указанной нагрузки, не опубликованный
университетом total и не доказательство достаточного полного бюджета.
